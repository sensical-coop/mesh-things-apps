Mesh Things trata una malla LoRa de [Meshtastic](https://meshtastic.org/) como una flota de dispositivos registrados. Las pasarelas publican paquetes protobuf en un broker MQTT. La plataforma descifra esos paquetes con la clave de la malla, guarda las lecturas y las sirve por una API HTTP y la consola.

Cada etapa guarda un tipo de dato distinto. El bus de mensajes lleva los paquetes en bruto, PostgreSQL guarda el registro de dispositivos e InfluxDB guarda las mediciones.

```mermaid
flowchart TD
  radios["Radios de la malla"] --> mqtt["Broker MQTT"]
  mqtt --> decoder["Descifrado"]
  decoder --> registry["Registro en PostgreSQL"]
  decoder --> series["Series temporales en InfluxDB"]
  decoder --> archive["Archivo Parquet"]
  registry --> console["API y consola"]
  series --> console
```

## Usuarios previstos

- Propietarios que operan una o varias mallas y necesitan un registro duradero de los datos de sus sensores.
- Quien quiera un aviso cuando un nodo deja de transmitir, un sensor se queda en un valor o un valor sale de su rango válido.
- Equipos que calculan canales extra a partir de las lecturas en bruto, con una calibración que puede cambiar con el tiempo.
- Operadores que importan tráfico de un broker MQTT remoto o que publican un subconjunto de lecturas para otra persona.
- Quien necesite acceso de solo lectura a una malla pública.

## Procesamiento de paquetes

1. **Ingesta.** El tráfico del broker MQTT se copia como paquetes en bruto. El broker puede ser el de esta instancia o un broker remoto registrado como [fuente](/sources).
2. **Descifrado.** El descifrado usa la clave precompartida de la malla y convierte cada paquete en datos estructurados. Se descartan los paquetes de pasarelas desconocidas y de nodos rechazados.
3. **Catalogación.** Cada paquete actualiza el registro. En PostgreSQL se crean o actualizan los dispositivos, las variantes de telemetría y los canales de medida.
4. **Almacenamiento.** Las lecturas descifradas se escriben en InfluxDB. Los dispositivos que lo activan se archivan además en ficheros Parquet por horas.
5. **Procesamiento.** Los detectores evalúan las lecturas que entran. Los trabajos programados aplican plantillas y comprobaciones de completitud sobre el histórico guardado.
6. **Acceso.** La API de registro gestiona cuentas, mallas, dispositivos y el catálogo. La API de lecturas sirve series, últimos valores, exportaciones y el archivo. La consola se apoya en ambas.

## Almacenamiento de datos

| Datos | Almacén |
| --- | --- |
| Cuentas, mallas, claves, dispositivos, catálogo, plantillas | PostgreSQL |
| Telemetría, posiciones, información de nodo, canales derivados, métricas de calidad, alarmas | InfluxDB |
| Eventos descifrados archivados, para los dispositivos que lo activan | Almacenamiento de objetos compatible con S3, en formato Parquet |

El contrato HTTP es un documento OpenAPI en `/schema`, en el host de la API, con una interfaz Swagger. Esa referencia se mantiene aparte de esta guía.
